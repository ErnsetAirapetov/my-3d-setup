# tools/storage/ — система хранения

План модульной системы хранения инструментов и расходников. Идея — **напечатать на самом принтере**: это и тренировка печати, и решение задачи под себя.

## Зачем своя система, а не «купить органайзер»

- Размеры подгоняются под **твой** набор инструментов и доступное место.
- Расширяется по мере роста инвентаря (купил новое — напечатал ячейку).
- Предсказуемое место для каждого предмета → меньше теряется мелочь, быстрее работа.
- Это бенчмарк качества печати (если кубики собираются криво — поправить калибровку).

## Что нужно решить **до** печати

1. **Куда поставим.** Стол / полка / стенка / выдвижной ящик — сильно влияет на форм-фактор.
2. **Какой объём.** Это узнаём из [../inventory.md](../inventory.md) — фотки и список инструментов соберут картину.
3. **Какие предметы под рукой каждый день, какие — раз в месяц.** Это диктует, что положить наверху, а что в глубину.
4. **Защита от пыли** — нужна или нет. Если принтер стоит в пыльном помещении (мастерская, гараж) — закрытое хранение; если в комнате — открытые ячейки удобнее.

## Варианты систем

### 1. Gridfinity — рекомендую для старта

Самая популярная модульная система в 3D-печатающем сообществе. Базовая сетка `42 × 42 мм`, два уровня сборки:

- **Baseplate** — большой поддон с сеткой (нижний уровень). Можно сделать любого размера: `2×3`, `5×7`, `10×10` и т.п. — по доступной площади.
- **Bins** — контейнеры разных размеров (`1×1×3u`, `2×2×6u`, `3×1×4u` и т.д.), которые вставляются в сетку. Магниты или прижим.

**Плюсы:** огромная библиотека готовых вставок (под штангенциркули, шестигранники, сопла, IPA-флаконы и т.п.). Совместимость с тысячами моделей других людей.
**Минусы:** ячейки относительно мелкие (`42 мм`); для крупных инструментов (большой шпатель, паяльник) приходится комбинировать или искать альтернативы.

**Источники:**
- Главный репозиторий: **«Gridfinity» Зака Фридмана** — поиск на Printables по `Gridfinity` (тысячи моделей).
- Готовые сборки baseplate + bins есть «всё в одном» комплектами.
- На YouTube — видео Зака Фридмана **«Gridfinity»** (англ.) — концепция за 15 минут.

### 2. Multiboard — современная альтернатива

Более новая система, ориентирована на **стенки** и крупные элементы. Размер ячейки `25 × 25 мм`, инфраструктура поверх — `156 × 156 мм` плитки. Гибче, но экосистема ещё догоняет Gridfinity.

**Когда брать:** если основное хранение будет **на стене**, не на столе.

### 3. Печатные перегородки в существующий ящик

Если уже есть выдвижной ящик / коробка — сделать **перегородки под него**. Быстро, дёшево, но не масштабируется.

**Когда брать:** есть готовый ящик и не хочется городить с нуля.

### 4. Кастомные tool holder под конкретный набор

Печатается **одна** деталь, в которую помещаются все нужные инструменты в фиксированных позициях. Под штангенциркуль, шестигранники, кусачки и т.п. — отдельный держатель.

**Когда брать:** инвентарь маленький и стабильный, не планируется рост.

## Рекомендация по дефолту

**Gridfinity.** Причины:
- Самая большая готовая библиотека под 3D-печатные инструменты (есть готовые держатели именно под штангенциркуль, шестигранники, кусачки flush cutters, иглы для прочистки сопла, бутыли IPA).
- Хорошая «школа» FDM: модули требуют точной XY-калибровки, и хорошо собранный Gridfinity = подтверждение что калибровка прошла успешно.
- Расширяемость без переделки.

## Процесс

1. **Сделать инвентаризацию** в [../inventory.md](../inventory.md). Без этого любой план хранения будет вилами по воде.
2. **Замерить** размеры ключевых инструментов (длина, диаметр) — это укажет, какие ячейки нужны.
3. **Определить место** на столе / полке для baseplate. Замерить доступную площадь.
4. **Решить:** Gridfinity / Multiboard / другое. Зафиксировать решение в этом файле в секции «Решение».
5. **Сначала откалибровать принтер** до уровня, где xyz-cube выходит ±0.1 мм. Иначе модули не сядут друг в друга.
6. **Печатать поэтапно:** сначала baseplate → потом несколько универсальных bin-ов → потом специализированные держатели по мере необходимости.
7. **Каждый напечатанный модуль** записывать в `printed.md` рядом с этим README (имя файла, источник, дата печати, заметки по подгонке).
