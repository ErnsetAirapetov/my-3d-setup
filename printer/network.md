# Сетевые координаты принтера

Зафиксированные адреса для доступа к принтеру в локальной сети.

## Базовые

| Параметр | Значение |
| --- | --- |
| Локальный IP (основной, стабильный) | `192.168.1.133` (DHCP-резервация по Wi-Fi MAC, проверено ребутами 2026-04-26) |
| Запасной IP (если резервация на роутере слетит) | `192.168.1.134` |
| MAC по `/detail` и `~M115` | `24:A1:0D:B2:AA:8E` |
| MAC на проводе (Wi-Fi STA, видит роутер и ARP) | `30:4A:26:17:8F:37` |
| Hostname | `adventurer5m-pro` _(резервировано на роутере, проверить DNS-резолв в LAN)_ |
| Сеть | домашний Wi-Fi |

### Два MAC у одного принтера

У Wi-Fi чипа ESP32, который стоит в Adventurer 5M Pro, в EFUSE зашито несколько MAC-адресов: отдельные для Wi-Fi STA, Wi-Fi AP, BLE и ETH. FlashForge через `/detail` и `~M115` отдаёт «парадный» MAC `24:A1:0D:B2:AA:8E` (вероятно, это ETH или BLE). А **на проводе при подключении к домашнему Wi-Fi** принтер использует другой MAC из той же ESP32 — `30:4A:26:17:8F:37`. Оба OUI принадлежат Espressif Inc., оба MAC статичны (зашиты в железо, не рандомизируются между ребутами).

**Что было и как починили:** изначально DHCP-резервация на OpenWRT была сделана на «парадный» MAC `24:A1:0D:B2:AA:8E`, поэтому сервер DHCP её не применял (на проводе видел другой MAC) и принтер получал свободный IP — попеременно `.134` или `.133`. После того как 2026-04-26 на роутере резервацию перепривязали к реальному Wi-Fi MAC `30:4A:26:17:8F:37`, IP стабилизировался на `.133` и сохраняется между ребутами. Адрес `.134` оставлен как запасной — на случай, если резервация снова слетит или роутер потеряет конфиг.

**Как узнать текущий IP сейчас:**
- Посмотреть на сенсорном экране принтера (Settings → Network info).
- Если есть доступ хотя бы к одному IP-кандидату — `POST /detail`, поле `ipAddr` отдаст актуальный.

## Камера

- Поток (MJPEG): `http://192.168.1.134:8080/?action=stream`.
- Снимок: эндпоинт `?action=snapshot` принтером **не отдан** (в стоке поток без отдельного снимка).
- В состоянии `ready`/idle камера на стоковой прошивке ведёт себя нестабильно: иногда отдаёт поток, иногда сразу закрывает соединение (`Remote end closed connection without response`), иногда уходит в тишину и порт 8080 не отвечает даже на TCP-handshake (`connection timed out`). В режиме печати — стабильнее. Учитывать при сборке таймлапсов: запускать захват уже после старта печати.
- **Single-client limit.** Стоковый mjpg-streamer пускает одного клиента за раз и держит низкий TCP backlog — пока кто-то один (браузер, FlashForge-приложение, скрипт) консьюмит поток, любая другая попытка подключения к 8080 отваливается **на стадии TCP-handshake** (timeout). Параллельно «смотреть в браузере + писать таймлапс» нельзя без замены камеры или прокси-сервиса на стороне.
- URL потока также возвращается в поле `cameraStreamUrl` ответа `POST /detail` на 8898 — лучше брать оттуда, а не хардкодить.

## Открытые порты

Сканирование от 2026-04-26:

| Порт | Протокол | Что отдаёт |
| --- | --- | --- |
| 8080 | HTTP (mjpg-streamer) | поток с камеры |
| 8898 | HTTP REST | Flashforge HTTP API (требует LAN-mode + SN/checkCode) |

Порты 80, 443, 7125 (Moonraker), 5000/5001 — закрыты на стоке.

## TCP API (порт 8899)

Простой текстовый протокол: M-команды с префиксом `~`, разделитель `\r\n`, ответ заканчивается строкой `ok`.

Полезные команды (проверено):

| Команда | Что возвращает |
| --- | --- |
| `~M115` | модель, прошивка, SN, рабочее поле X/Y/Z, MAC, Tool count |
| `~M105` | температуры: T0/T1 (нозлы), B (стол), формат `current/target` |
| `~M27` | прогресс печати, текущий слой |
| `~M114` | текущая позиция X/Y/Z |
| `~M119` | состояние эндстопов и MachineStatus (READY/PRINTING/...) |
| `~M650` | возвращает `X: 1.0 Y: 0.5` (назначение TBD) |
| `~M661` | список файлов в `/data/` |

Пример из bash:

```bash
exec 3<>/dev/tcp/192.168.1.134/8899
printf '~M115\r\n' >&3
timeout 1 cat <&3
exec 3<&-; exec 3>&-
```

## HTTP API (порт 8898)

REST API. Все эндпоинты — POST с JSON-телом, в теле обязательны `serialNumber` и `checkCode`. **Требует включённого LAN-режима** на принтере, иначе любой запрос возвращает `{"code":-2,"message":"Lan mode error"}`.

В UI принтера переключатель называется **LAN-only**. Под ним показывается «Printer ID» — это и есть `checkCode` = `a3356b04`. **Включён 2026-04-26.**

Эндпоинты:

| Путь | Назначение |
| --- | --- |
| `POST /detail` | детальный статус: температуры, прогресс печати, состояние фильтров и света, кумулятивная статистика |
| `POST /product` | матрица того, чем можно управлять (свет, вентиляторы, температуры) |
| `POST /control` | команды управления |

Пример вызова:

```bash
curl -s -X POST http://192.168.1.134:8898/detail \
  -H 'Content-Type: application/json' \
  -d '{"serialNumber":"SNMOME9C00678","checkCode":"a3356b04"}'
```

### Полезные поля из `/detail`

Подмножество, которое нам интересно для мониторинга и калибровок:

| Поле | Что значит |
| --- | --- |
| `firmwareVersion` | прошивка (на момент 2026-04-26 — `3.2.7`) |
| `name` | Serial Number |
| `ipAddr`, `macAddr` | сетевые идентификаторы |
| `measure` | рабочее поле, например `220X220X220` |
| `nozzleCnt`, `nozzleModel` | количество и диаметр сопла (`0.4mm`) |
| `status` | `ready` / `printing` / `paused` / ... |
| `leftTemp` / `leftTargetTemp` | текущая и целевая температура hotend |
| `platTemp` / `platTargetTemp` | текущая и целевая температура стола |
| `chamberTemp` / `chamberTargetTemp` | температура камеры (на 5M Pro есть датчик, нагрева камеры нет) |
| `tvoc` | показания TVOC-сенсора (датчик летучих органических соединений) |
| `doorStatus` | `close` / `open` |
| `lightStatus` | `open` / `close` (свет внутри) |
| `internalFanStatus`, `externalFanStatus` | состояние фильтрующих вентиляторов |
| `coolingFanSpeed`, `chamberFanSpeed` | скорости вентиляторов |
| `printProgress`, `printLayer`, `targetPrintLayer` | прогресс текущей печати |
| `printFileName`, `printFileThumbUrl` | текущий файл и превью |
| `currentPrintSpeed`, `printSpeedAdjust` | скорость и live-speed override |
| `cumulativeFilament` | прожжено филамента всего, в метрах |
| `cumulativePrintTime` | общее время печати, в минутах |
| `remainingDiskSpace` | свободное место в `/data/` (в GB) |
| `cameraStreamUrl` | URL потока с камеры |
| `autoShutdown`, `autoShutdownTime` | авто-выключение (вкл/выкл и таймер в минутах) |
| `zAxisCompensation` | live Z-offset |
| `errorCode` | код ошибки, пусто — если ОК |

## История изменений

- **2026-04-26** — принтер первый раз подключён к Wi-Fi, IP `192.168.1.134`. Через TCP `~M115` подтверждены SN/MAC/прошивка/рабочее поле.
- **2026-04-26** — на принтере включён режим **LAN-only**. HTTP REST API на 8898 заработал с `serialNumber=SNMOME9C00678` + `checkCode=a3356b04`. Подтверждены поля `/detail` и матрица `/product`.
- **2026-04-26** — на OpenWRT-роутере выдана **DHCP-резервация** `24:A1:0D:B2:AA:8E` ↔ `192.168.1.134`, hostname `adventurer5m-pro`.
- **2026-04-26** — после ребута принтер взял `192.168.1.133` вместо зарезервированного `.134`. Расследование показало: у ESP32 два MAC, в Wi-Fi уходит `30:4A:26:17:8F:37`, а резервация была на «парадный» `24:A1:0D:B2:AA:8E`.
- **2026-04-26** — на OpenWRT-роутере **перепривязана DHCP-резервация** на правильный Wi-Fi STA MAC `30:4A:26:17:8F:37`. Проверено ребутом — IP стабильно `.133`. Основным считаем `.133`, `.134` оставлен как запасной (на случай если резервация слетит).
