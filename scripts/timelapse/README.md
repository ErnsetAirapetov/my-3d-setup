# scripts/timelapse — таймлапс с камеры принтера

Интервальный захват кадров с MJPEG-потока Flashforge Adventurer 5M Pro
(`http://192.168.1.134:8080`) и сборка mp4 через ffmpeg. Работает на стоке,
без модов и без Klipper.

Пока MVP: захват по интервалу (например, кадр каждые 15 секунд), без layer-trigger.
Когда переедем на Klipper — заменим на штатный `moonraker-timelapse`.

## Что нужно

- **Python 3.8+** в PATH (проверить: `python --version`).
- **ffmpeg** в PATH (проверить: `ffmpeg -version`). На Windows проще всего —
  через `winget install Gyan.FFmpeg` или скачать с ffmpeg.org и добавить в PATH.
- Принтер в сети, LAN-mode включён (по умолчанию у нас уже так — см.
  [printer/network.md](../../printer/network.md)).

## Как запускать

Из папки `scripts/timelapse/`:

```bash
# Сначала — проба, что камера вообще отдаёт кадр
python timelapse.py --probe

# Если ОК — стартуй захват (в момент, когда печать уже идёт)
python timelapse.py --label benchy
```

По умолчанию: интервал 15 сек, итоговое видео 30 fps, IP `192.168.1.134`.
Кадры пишутся в `output/<timestamp>/frame_NNNNNN.jpg`. Папка `output/`
исключена из git (см. локальный `.gitignore`).

Остановка — `Ctrl+C`. После остановки скрипт автоматически собирает
`output/<timestamp>.mp4` через ffmpeg.

> **Важно:** на стоковой прошивке AD5M Pro камера почти не стримит, пока
> принтер в `ready`/idle. Поток оживает, когда печать стартует (или когда
> FlashForge-приложение / веб-UI принтера держит соединение). Поэтому
> запускать `timelapse.py` имеет смысл уже после того, как печать поехала.
> Если `--probe` падает с `Remote end closed connection without response` —
> это нормально для idle, не баг.

## Параметры

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `--interval` | `15` | секунд между кадрами |
| `--fps` | `30` | FPS итогового видео (большие значения → быстрее ускорение) |
| `--label benchy` | пусто | добавляет суффикс к имени папки, удобно метить печати |
| `--ip` | `192.168.1.134` | IP принтера, на случай смены |
| `--stream-url` | пусто | принудительный URL потока (по умолчанию берём из `/detail` → `cameraStreamUrl`) |
| `--output-dir` | `./output` | корень для папок с кадрами |
| `--no-video` | off | оставить только кадры, не звать ffmpeg |
| `--probe` | off | один раз дёрнуть камеру, сохранить `probe.jpg` и выйти — для проверки |

## Прикидка длительности видео

Полезно понимать, насколько ускоряется реальное время:

```
длительность_видео = (длительность_печати) × (1 / interval) / fps
```

При `interval=15` и `fps=30`:

| Печать | Кадров | Видео |
| --- | --- | --- |
| 30 мин | 120 | 4 сек |
| 2 ч | 480 | 16 сек |
| 6 ч | 1440 | 48 сек |
| 12 ч | 2880 | 1 мин 36 сек |

Если печать длинная и хочется видео подлиннее — увеличь `interval`
(реже кадры) или уменьши `--fps` (медленнее воспроизведение).

## Типичные грабли

- **`Remote end closed connection without response`** или таймаут на пробе
  при холостом принтере — нормально, стоковая камера в idle не стримит.
  Запускай скрипт уже когда печать поехала.
- **`ffmpeg не найден в PATH`** — кадры сохранены, можно собрать руками:
  ```bash
  ffmpeg -framerate 30 -i output/2026-04-26_19-00-00/frame_%06d.jpg \
         -c:v libx264 -pix_fmt yuv420p output/timelapse.mp4
  ```
- **`поток открылся, но JPEG не пришёл`** — обычно означает, что камера
  занята другим клиентом (FlashForge-приложение, открытая вкладка с потоком
  в браузере). Закрой лишних клиентов, попробуй снова.
- **Кадры тёмные / пересвет / сдвиг** — стоковая камера так умеет.
  На длинных печатях полезно стабилизировать освещение (отдельная LED-подсветка).
