# scripts/timelapse — таймлапс с камеры принтера

Интервальный захват кадров с MJPEG-потока Flashforge Adventurer 5M Pro
(`http://<ip>:8080/?action=stream`) и сборка mp4 через ffmpeg. Работает на стоке,
без модов и без Klipper.

Основной IP принтера — `192.168.1.133` (он же дефолт скрипта). Если резервация
DHCP вдруг слетит и принтер уедет на `.134` — запускай с `--ip 192.168.1.134`.
Подробнее про два IP и два MAC — в [printer/network.md](../../printer/network.md).

Пока MVP: захват по интервалу (например, кадр каждые 15 секунд), без layer-trigger.
Когда переедем на Klipper — заменим на штатный `moonraker-timelapse`.

## Что нужно

- **Python 3.8+** в PATH (проверить: `python --version`).
- **ffmpeg** в PATH (проверить: `ffmpeg -version`). На Windows проще всего —
  через `winget install Gyan.FFmpeg` или скачать с ffmpeg.org и добавить в PATH.
- Принтер в сети, LAN-mode включён (по умолчанию у нас уже так — см.
  [printer/network.md](../../printer/network.md)).

## Как запускать

Скрипт лежит в `scripts/timelapse/`, запускается из этой папки:

```bash
cd scripts/timelapse
python timelapse.py [параметры]
```

Дефолты: интервал захвата **15 сек**, итоговое видео **30 fps**, IP **`192.168.1.133`**.
Кадры пишутся в `output/<timestamp>_<label>/frame_NNNNNN.jpg`. Папка `output/`
исключена из git. Остановка — `Ctrl+C`, после чего скрипт сам собирает
`output/<timestamp>_<label>.mp4` через ffmpeg.

> **Важно перед запуском.** У стоковой камеры на AD5M Pro **single-client лимит**:
> один клиент за раз. Если в браузере открыта вкладка `?action=stream` или
> запущено FlashForge-приложение — слот занят, скрипт получит отказ.
> **Закрой все вкладки и приложения, дёргающие камеру**, прежде чем запускать.
> В состоянии idle камера капризная — запускать имеет смысл уже после старта печати.

### Шаг 1. Проверить камеру (probe)

Один кадр, сохранить в `probe.jpg`, выйти. Полезно перед боевым стартом:

```bash
# Дефолтный IP (.133)
python timelapse.py --probe

# Если принтер уехал на запасной .134
python timelapse.py --probe --ip 192.168.1.134
```

### Шаг 2. Боевой запуск (примеры)

```bash
# Дефолт: интервал 15 сек, fps 30, IP .133
python timelapse.py

# С меткой модели (попадёт в имя папки и mp4)
python timelapse.py --label benchy

# Если принтер уехал на запасной .134
python timelapse.py --ip 192.168.1.134 --label benchy

# Короткая печать (~30 мин) — частый шаг, плотное видео
python timelapse.py --interval 5 --label cube

# Длинная печать (~6 часов) — редкий шаг
python timelapse.py --interval 30 --label dragon

# Замедленное воспроизведение (60 fps вместо 30 — плавнее, но длиннее)
python timelapse.py --interval 10 --fps 60 --label benchy

# Только кадры, без сборки видео (соберёшь руками потом)
python timelapse.py --interval 15 --no-video --label benchy

# Складывать кадры в другое место
python timelapse.py --output-dir D:/timelapse-archive --label benchy

# Принудительный URL потока (если IP/путь нестандартный)
python timelapse.py --stream-url "http://192.168.1.133:8080/?action=stream"
```

После `Ctrl+C` файлы окажутся, например, тут:

```
scripts/timelapse/output/
  2026-04-26_19-00-12_benchy/
    frame_000000.jpg
    frame_000001.jpg
    ...
  2026-04-26_19-00-12_benchy.mp4
```

## Параметры

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `--interval` | `15` | секунд между кадрами |
| `--fps` | `30` | FPS итогового видео (большие значения → быстрее ускорение) |
| `--label benchy` | пусто | добавляет суффикс к имени папки, удобно метить печати |
| `--ip` | `192.168.1.133` | IP принтера, на случай смены (запасной — `.134`) |
| `--stream-url` | пусто | принудительный URL потока (по умолчанию берём из `/detail` → `cameraStreamUrl`) |
| `--output-dir` | `./output` | корень для папок с кадрами |
| `--no-video` | off | оставить только кадры, не звать ffmpeg |
| `--probe` | off | один раз дёрнуть камеру, сохранить `probe.jpg` и выйти — для проверки |

## Шаг записи кадров: как выбрать

Идея простая: целиться на видео длиной **15–30 секунд** при дефолтных 30 fps.
Слишком частый шаг = огромный архив и тягучее видео. Слишком редкий = пропустишь
интересные моменты, видео будет дёрганым.

### Рекомендации по длительности печати

| Длительность печати | `--interval` | Кадров | Длина видео при `--fps 30` |
| --- | --- | --- | --- |
| 15–30 мин (мелкие тесты, калибровки) | `2`–`3` | 300–900 | 10–30 сек |
| 30–60 мин (средняя деталь) | `5` | 360–720 | 12–24 сек |
| 1–2 ч | `10` | 360–720 | 12–24 сек |
| 2–4 ч | `15` (дефолт) | 480–960 | 16–32 сек |
| 4–8 ч | `30` | 480–960 | 16–32 сек |
| 8–12 ч | `60` | 480–720 | 16–24 сек |
| 12–24 ч | `90`–`120` | 360–960 | 12–32 сек |
| 24+ ч | `180` и больше | по факту | 15–25 сек |

### Если хочется посчитать самому

```
длительность_видео_сек = длительность_печати_сек / (interval × fps)
```

Пример: печать 4 часа (`14400` сек), интервал `20`, `--fps 30`:
`14400 / (20 × 30) = 24` сек видео.

### Что меняет `--fps`

`--fps` управляет **скоростью воспроизведения** готового mp4, не захватом:

- `--fps 30` (дефолт) — стандартный кинематографический темп.
- `--fps 60` — то же количество кадров проигрывается **в два раза дольше** (плавнее, видео длиннее).
- `--fps 15` — **в два раза быстрее** воспроизведение (короче, более «лесенкой»).

То есть если кадры уже сняты с одним интервалом, можно переcобрать видео руками
с другим fps — кадры не теряются, меняется только скорость.

### Заметка про слои

На AD5M Pro один слой обычно печатается 30–90 секунд. Если хочется «один кадр
на слой» — поставь интервал ≈ 30–60 сек. Будет менее предсказуемо, чем чисто
интервальное по времени, но визуально приятнее: каждый кадр — новая высота.

## Типичные грабли

- **`Remote end closed connection without response` / `Empty reply from server` /
  `Operation timed out with 0 bytes received`** — все три варианта означают,
  что **слот камеры занят другим клиентом** или сервис на принтере «уснул».
  Закрой все вкладки `?action=stream` в браузере, выгрузи FlashForge-приложение,
  проверь, что нет активного коннекта (`Get-NetTCPConnection -RemoteAddress 192.168.1.133`
  в PowerShell — должен быть пустой результат либо только `TimeWait`). Если ничего
  не помогает — короткий ребут принтера.
- **TCP таймаут на этапе handshake (`Connection timed out` без `Connected`)** —
  принтер не отвечает по этому IP. Скорее всего, **DHCP-резервация на роутере
  слетела и принтер уехал на запасной `.134`** (см. [printer/network.md](../../printer/network.md)
  про два IP). Запусти с `--ip 192.168.1.134`. Актуальный IP видно на сенсорном
  экране принтера: Settings → Network info.
- **`ffmpeg не найден в PATH`** — кадры сохранены, видео можно собрать руками:
  ```bash
  ffmpeg -framerate 30 -i output/2026-04-26_19-00-00_benchy/frame_%06d.jpg \
         -c:v libx264 -pix_fmt yuv420p \
         -vf "scale=trunc(iw/2)*2:trunc(ih/2)*2" \
         output/manual.mp4
  ```
- **Кадры тёмные / пересвет / сдвиг** — стоковая камера так умеет.
  На длинных печатях полезно стабилизировать освещение (отдельная LED-подсветка).
- **В состоянии `ready`/idle камера капризная** — иногда отдаёт поток, иногда нет.
  Запускай скрипт уже после старта печати, тогда стабильнее.

## Что улучшить потом

- Layer-trigger через polling `/detail` на `:8898` — ловить смену слоя
  и парковать голову через G-code в OrcaSlicer ("Smooth Timelapse").
- Авто-стоп по статусу принтера (когда печать завершилась).
- Финальный «freeze frame» на N секунд в конце видео.
- Переезд на Klipper → выкинуть это и поставить `moonraker-timelapse`.
